1.2.2 Lógica de validación RFC (RfcValidador)
Crear una clase de dominio (librería OilsMexico.Domain o Application) con reglas basadas en el Anexo de la Guía para la validación de RFC del SAT:
		bool EsValido(string? rfc) → valida estructura y, opcionalmente, semántica (fecha para PF).
		Formatos aceptados:
		PF: 10 caracteres: letra (consonante o X/Y/Z/H) + 6 dígitos (YYMMDD) + 3 alfanuméricos.
		PM: 12–13 caracteres: 3–4 letras (clave de subdivisión) + 2 dígitos (año) + 6 dígitos (inscripción) + 3 alfanuméricos.
		Permitir cadena vacía → considerada como "SIN RFC" (solo para público en general).
		Validaciones complementarias:
		Solo mayúsculas, sin espacios, sin guiones.
		Primera letra de PF no puede ser vocal, "U", "N", etc. (se aplica el RFC de presentación del SAT).
		(Opcional, para los que lo necesiten) Validar que los 6 dígitos de PF tengan una fecha plausible (30/31 de cada mes, etc.).
		Retornar RfcValidacionResultado con EsValido, TipoPersona detectado, y Errores (lista de mensajes).

2.2 Propuesta de diseño
2.2.1 Modelo de datos (BD)
Agregar columnas a la tabla usuarios (vía SchemaPatch, idempotente):
		segundo_factor_activo boolean NOT NULL DEFAULT false
		segundo_factor_secreto varchar(128) → secreto TOTP en base32 (no cifrado, se comunica al usuario vía QR en un solo intento de activación; el DB debería estar protegido)
		segundo_factor_token varchar(64) y segundo_factor_token_hasta_utc timestamptz → token temporal de paso 1 del flujo 2FA (single-use, expira 5 min)
		cantidad_intentos_sucios no es necesario; no se toca.
2.2.2 Lógica de cambio de contraseña
		Nuevo servicio ICambioContrasenaService (o exporlo desde AuthService) con:
		Task<CambioContrasenaResult> EjecutarAsync(int usuarioId, string contrasenaActual, string contrasenaNueva)
		Validaciones:
		contrasenaActual coincide con el hash actual (usando la misma lógica de VerificarConUpgradeAsync de AuthService).
		contrasenaNueva longitud mínima 8, máximo 100.
		No puede ser igual a contrasenaActual.
		(Opcional) No igual a los últimos 5 hashes (se pueden guardar con bucles o un simple filtro contra el historial de la BD).
		Acciones:
		Hash de la nueva contraseña con PasswordHasher<Usuario> (formato Identity v3$) → sobreescribe password_hash.
		Limpia pin_hash si el usuario usaba PIN legado.
		Invalida todas las sesiones abiertas del usuario: UPDATE usuarios SET sesion_token = NULL WHERE id = @usuarioId.
		Invalida tokens temporales de 2FA pendientes de ese usuario (opcional, para cerrar el paso 2FA).
		(Opcional) Graba línea en un log de auditoría (tabla auditoria o configuracion como log, o una tabla propia si el proyecto ya lo tiene). Se recomienda: INSERT INTO auditoria (usuario_id, accion, detalle, fecha).
2.2.3 Lógica de 2FA (TOTP)
		Implementación sin dependencias pesadas:
		Clase TotpService (aplica RFC 6238), usando HMACSHA1 (librería nativa de .NET).
		Métodos:
		string GenerarSecreto() → devuelve secreto base32 de 32 bytes (en base32, 40 caracteres)
		string ObtenerUrlProvisión(string nombre, string secret, string issuer = "OilsMexico")
		bool Verificar(string codigo, string secret, TimeSpan? tolerancia = null) → 6 dígitos, 30s step, ventana de 30 segundos (1 tiempo). TimeSpan.FromSeconds(30).
		bool EsValido(string codigo, string secret) → verifica tiempo actual (se considera válido si el código coincide en el intervalo actual o uno previo).
		Método de habilitación:
		Task<Resultado> ActivarSegundoFactorAsync(int usuarioId, string codigo):
		GenerarSecreto(), guardar el secreto y el segundo_factor_activo = true
		Retornar el secreto y la URL de provisión para que el usuario escanee el QR.
		Task<Resultado> VerificarCodigoAsync(int usuarioId, string codigo):
		Verificar con TOTP y el secreto guardado.
		Registrar éxito en log.
		Método de deshabilitación:
		Task<Resultado> DesactivarSegundoFactorAsync(int usuarioId) → solo si está activo; pide confirmación (y quizás código actual). Borra secreto y fila de activación.
2.2.4 Flujo completo de login con 2FA
Paso 1 — LoginAsync(identificador, password) (sin cambios de comportamiento)
		Si la contraseña es correcta, y el usuario tiene segundo_factor_activo = true, no se crea sesión aún.
		Retorna LoginResultado extendido con:
public sealed record LoginResultado(
    SesionDto? Sesion,
    string? MensajeError = null,
    DateTime? BloqueadoHastaUtc = null,
    bool Necesita2Fa = false,   // nuevo
    int? UsuarioId = null);     // nuevo (solo si Necesita2Fa)
		El UsuarioId se envía para que el frontend sepa qué cuenta y pueda llamar el paso 2 (sin exponer datos sensibles).
Paso 2 — Login2FASync(int usuarioId, string codigo)
		Verifica que el usuario exista, esté activo, no esté bloqueado, y tenga segundo_factor_activo = true.
		Además, verifica que exista un segundo_factor_token válido y no expirado (token generado en el paso 1; single-use).
		Verifica que el código TOTP sea válido.
		Si todo ok:
		Consumir el token (borrarlo de la BD).
		Crear sesión completa (mismo patrón que el LoginAsync exitoso actual: setear SesionToken, resetear bloqueos, etc.).
		Retornar SesionDto.
		Si falla (código incorrecto, expirado, token no existe o no coincide, usuario sin 2FA), retorna LoginResultado con Necesita2Fa = false y un mensaje de error, sin crear sesión.
Consideraciones de seguridad:
		El flujo 2FA se limita a un solo paso y un solo token (se elimina al usar el código).
		El token de paso 1 expira en 5 minutos; si expira, el usuario debe volver a iniciar sesión.
		El código de 2FA no se guarda en ningún lado (solo se compara con el algoritmo TOTP); el secreto se almacena una sola vez.
		Si el usuario no tiene 2FA activo, LoginAsync sigue funcionando como antes (sin 2FA).
		Si el usuario tiene 2FA activo y entra el código correcto, se inicia sesión normal.
2.2.5 Cambio de contraseña + 2FA
		Si el usuario tiene 2FA activo, no se obliga a usar 2FA mientras cambia la contraseña (para no anular el flujo de suscripción). Se verifica la contraseña actual y se reemplaza. Se la notifica a la persona qué guardó el 2FA.
		Si el usuario pierde el acceso (no recuerda la contraseña ni tiene 2FA), el admin lo desbloquea o reinicia la 2FA.
